# Исходное техническое задание

Восстановлено из разговора «Заставка на МАК».

Ты — senior macOS engineer + Apple-style UI/visual designer + 3D graphics engineer.

Нужно создать полноценный проект заставки для macOS с реалистичной 3D Землёй, отображением текущего положения дня/ночи и локального времени выбранных городов.

ВАЖНО:
Это должен быть не просто визуальный прототип, а реально собираемый и устанавливаемый проект для актуальной версии macOS на Apple Silicon (мой Mac — 13-дюймовый MacBook на M1).

Перед началом реализации:

1. Определи актуальный на сегодняшний день поддерживаемый Apple способ создания сторонней заставки для последней версии macOS.
2. Не используй устаревший API просто потому, что он встречается в старых примерах.
3. Если классический формат .saver / ScreenSaver framework имеет ограничения на современной macOS, сначала объясни это в README и выбери наиболее надёжный современный вариант.
4. Цель — чтобы пользователь мог выбрать эту сцену как заставку macOS либо получить максимально близкое к нативной системной заставке поведение, разрешённое современной macOS.
5. Не используй скрытые фоновые службы, launch daemons или другие ненужные системные компоненты.
6. Установка и удаление должны быть максимально простыми.

==================================================
ОБЩАЯ КОНЦЕПЦИЯ
==================================================

Создать кинематографичную, спокойную заставку в эстетике Apple:

— большая реалистичная Земля;
— тёмный глубокий космос;
— очень деликатные звёзды;
— слегка заметный Млечный Путь;
— Луна вдалеке;
— физически правдоподобное освещение Земли Солнцем;
— хорошо различимая граница дня и ночи;
— реальные текущие дата/время и положение Солнца;
— Земля медленно вращается;
— выбранные города отображаются непосредственно на поверхности Земли;
— возле каждого видимого города находятся небольшие круглые аналоговые часы с локальным временем этого города.

Сцена должна выглядеть дорого, минималистично и спокойно, а не как научный симулятор или перегруженный dashboard.

Ориентир по визуальному языку:
Apple / macOS / visionOS:
минимум визуального шума, мягкие переходы, глубина, качественная типографика, glass-like элементы в очень умеренном количестве.

==================================================
КОМПОЗИЦИЯ
==================================================

Земля — главный объект.

На экране MacBook 13":

— диаметр видимой Земли должен занимать приблизительно 50–70% меньшего измерения экрана;
— Земля должна быть крупной;
— композиционно она должна находиться преимущественно в нижней/центральной части экрана;
— верхняя/центральная область должна оставаться достаточно спокойной, чтобы системный интерфейс блокировки/входа macOS не конфликтовал с основными элементами сцены;
— при разных aspect ratio композиция должна адаптироваться автоматически.

Не делать Землю маленьким шариком в центре космоса.

Мы должны чувствовать близость к Земле.

Часть планеты при необходимости может немного уходить за нижнюю границу экрана.

КОСМОС
==================================================

Фон практически чёрный.

Добавить:

— реалистичное звёздное поле;
— небольшую вариативность яркости звёзд;
— очень слабый Млечный Путь;
— никакой чрезмерной насыщенности;
— никакой ярко-синей/фиолетовой "игровой" туманности.

Млечный Путь должен быть заметен только после нескольких секунд взгляда.

Можно добавить едва заметный эффект пространственного движения звёзд, но:

— движение должно быть чрезвычайно медленным;
— никакого эффекта hyperspace;
— никаких полос;
— не должно отвлекать от Земли.

==================================================
ЛУНА
==================================================

Добавить Луну в глубине пространства.

Предпочтительное начальное расположение — справа от Земли.

Она должна:

— выглядеть физически правдоподобно;
— быть значительно меньше Земли;
— находиться визуально далеко;
— иметь соответствующую фазу освещения;
— не конкурировать с Землёй;
— двигаться крайне медленно.

Композиция должна работать и без Луны, поэтому сделай её включаемой/выключаемой через конфигурацию.

==================================================
ЗЕМЛЯ
==================================================

Использовать качественную сферическую модель.

Необходимо:

— карта поверхности Земли высокого разрешения;
— океаны;
— материки;
— облака;
— атмосфера;
— мягкое атмосферное свечение по краю;
— ночная сторона;
— при возможности очень деликатные городские огни на ночной стороне.

Не делать атмосферный glow чрезмерно голубым.

Earth shader должен учитывать направление на Солнце.

Должна быть видна реальная линия терминатора:

DAY
→ twilight
→ NIGHT

Положение освещённой области должно рассчитываться от текущей UTC даты и времени.

То есть если в реальном мире сейчас освещена Европа, Азия или Америка, визуализация Земли должна соответствовать реальному положению Солнца.

Не требуется астрономическая точность уровня NASA, но положение дня/ночи должно быть корректным.

==================================================
ВРАЩЕНИЕ ЗЕМЛИ
==================================================

Земля должна вращаться непрерывно и очень плавно.

Важно:

не делай вращение слишком быстрым.

Это заставка, которую человек может видеть долго.

Нужна спокойная кинематографичная скорость.

Вращение может быть художественно ускорено относительно реальных 24 часов, но:

— день/ночь и локальное время городов должны оставаться реальными;
— положение городов относительно поверхности Земли всегда должно быть географически правильным.

Вынести скорость визуального вращения в настройку.

Например:

earthRotationSpeed = configurable

==================================================
ГОРОДА / ЧАСОВЫЕ ЗОНЫ
==================================================

Архитектура должна позволять легко добавлять и удалять города.

Каждый город описать структурой примерно:

City {
    name
    latitude
    longitude
    timeZoneIdentifier
}

Не использовать вручную заданный UTC offset.

Использовать системную TimeZone / IANA timezone database, чтобы автоматически учитывались:

— daylight saving time;
— зимнее/летнее время;
— локальные изменения часового пояса.

Начальный набор можно сделать:

Madrid
Singapore
New York

При этом список должен находиться в одном легко редактируемом конфигурационном месте.

Я позже добавлю/изменю города.

Не зашивать UI каждого города вручную.

==================================================
ГОРОД НА ПОВЕРХНОСТИ ЗЕМЛИ
==================================================

Для каждого города вычислить его реальную позицию на сфере по latitude/longitude.

Когда город находится на видимой стороне Земли:

показать около соответствующей точки небольшие круглые аналоговые часы.

ВАЖНО:

часы географически привязаны к городу,
НО сам циферблат всегда должен быть ориентирован лицом к зрителю.

Не наклонять циферблат по касательной к поверхности сферы так, чтобы часы становились нечитаемыми.

То есть:

позиция = следует за точкой города на Земле;
orientation = billboard / face camera.

==================================================
ДИЗАЙН ЧАСОВ
==================================================

Форма часов — круглая.

Это принципиально важно композиционно:

Earth = circle
Moon = circle
Clock = circle

Стиль:

— минималистичные аналоговые часы;
— без секундной стрелки;
— часовая стрелка;
— минутная стрелка;
— небольшие метки;
— очень качественный anti-aliasing;
— умеренная полупрозрачность;
— glass/material эффект в стиле macOS, но без чрезмерного blur;
— высокая читаемость на светлой и тёмной стороне Земли.

Под часами или внутри нижней части циферблата:

название города.

Также отображать AM / PM.

Например:

MADRID
08:34 PM

Но визуально главными остаются аналоговые стрелки.

AM/PM должен быть достаточно заметен, чтобы невозможно было перепутать утро и вечер.

Цифровое время можно сделать маленькой дополнительной подписью.

==================================================
ЧИТАЕМОСТЬ
==================================================

Это критическое требование.

Часы должны оставаться хорошо читаемыми независимо от:

— океана;
— облаков;
— пустыни;
— ночной части;
— дневной части;
— положения возле края Земли.

Можно использовать:

— adaptive contrast;
— мягкую тень;
— лёгкий outline;
— luminance-aware styling.

Но всё должно оставаться очень аккуратным.

==================================================
ПОВЕДЕНИЕ У КРАЯ ЗЕМЛИ
==================================================

Когда город приближается к краю видимого диска:

не нужно деформировать часы перспективой.

Вместо этого:

1. Часы остаются ориентированными к камере.
2. Начинают постепенно уменьшаться/затухать.
3. Когда точка города оказывается за горизонтом Земли, часы на поверхности исчезают.

Переход должен быть плавным.

Никаких резких появлений/исчезновений.

==================================================
ГОРОД НА ОБРАТНОЙ СТОРОНЕ ЗЕМЛИ
==================================================

Это важная особенность проекта.

Если выбранный город находится на обратной, невидимой стороне Земли:

его время всё равно должно быть доступно.

В этом случае создать небольшой отдельный круглый индикатор часов возле противоположного края композиции.

Пример:

если Луна расположена справа,
индикаторы скрытых городов располагаются слева.

Таким образом они визуально уравновешивают композицию.

Если Луна находится слева,
индикаторы переходят вправо.

Индикатор должен содержать:

— маленький аналоговый циферблат;
— название города;
— локальное время;
— AM/PM.

Он не должен выглядеть как HUD из компьютерной игры.

Очень минималистично.

==================================================
ПЕРЕХОД ВИДИМЫЙ ↔ СКРЫТЫЙ ГОРОД
==================================================

Когда Земля вращается и город уходит за горизонт:

часы на Земле плавно исчезают.

Одновременно соответствующий off-screen индикатор плавно появляется.

Когда город снова появляется:

происходит обратный переход.

Можно использовать мягкое crossfade / interpolation.

Не должно быть скачка.

==================================================
НЕСКОЛЬКО СКРЫТЫХ ГОРОДОВ
==================================================

Не допускать пересечений.

Spacing должен рассчитываться автоматически.

==================================================
ФИЗИКА ОСВЕЩЕНИЯ
==================================================

Нужно рассчитывать текущее положение Солнца по дате/времени.

Использовать UTC как базу.

Для каждой точки поверхности:

dot(normal, sunDirection)

определяет освещение.

Добавить мягкий twilight transition вместо жёсткой границы.

Cloud layer может освещаться немного иначе, создавая ощущение высоты.

==================================================
ПРОИЗВОДИТЕЛЬНОСТЬ
==================================================

Ориентироваться на Apple Silicon M1 и выше.

Заставка не должна:

— постоянно грузить CPU;
— расходовать большое количество энергии;
— использовать бессмысленно высокий frame rate.

Использовать Metal / SceneKit / RealityKit или иной современный Apple-native graphics stack — выбери наиболее подходящий вариант после анализа актуальных macOS API.

Предпочтение:
GPU rendering.

Target:
примерно 30 fps для screensaver вполне достаточно, если это визуально плавно.

При необходимости можно использовать adaptive frame rate.
